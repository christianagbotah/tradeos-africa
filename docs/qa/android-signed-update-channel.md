# Android signed preview update channel
The existing per-commit previews are not update-enrolled because CI debug signing is not a stable identity. The separate main-only, manually dispatched workflow requires an Android preview signing keystore backed up securely by the release owner, plus environment secrets ANDROID_PREVIEW_KEYSTORE_BASE64, ANDROID_PREVIEW_STORE_PASSWORD, ANDROID_PREVIEW_KEY_ALIAS, ANDROID_PREVIEW_KEY_PASSWORD and environment variable ANDROID_PREVIEW_CERT_SHA256 (64 hex digits, no colon). Do not store a keystore or passwords in Git. Use GitHub environment android-preview-signing with release approval and main-only deployment protection. The workflow validates the actual APK certificate and Android versionCode before publishing. The app discovers only newer enrolled GitHub preview releases and uses the Android browser/download/installer handoff, not silent installation. Device-level migration and two consecutive signed releases must be tested. Never uninstall an old APK until pending local records are synced and rejected records reviewed; the OS may require one-time migration if the prior certificate differs. Play Store/iOS production distribution is separate.
