# GitHub-first runtime retention and VPS footprint

The canonical TradeOS server entry is /home/lightworld/webapps/tradeos-staging. The application release root is /home/lightworld/releases/tradeos-staging. Keep only the active and independently verified rollback runtime under that root until an artifact-only rollback drill and revised shared deployment policy authorize removal of the local rollback. .lightworld is small release tracking metadata, not a duplicate app. Persistent database, media, configuration and backup paths remain protected.

The signed main-push runtime workflow builds, tests, checksums and attests the exact runtime on hosted GitHub runners. Temporary Actions artifacts are retained for 90 days rather than seven. The separate archive job verifies the exact archive digest, main commit and workflow signer before creating a full-SHA prerelease tag. It cannot overwrite an existing release or retarget a version. The repository is currently public: the permanent GitHub Releases job is deliberately skipped unless the repository is private or the owner explicitly approves public runtime publication through repository variable TRADEOS_PUBLIC_RUNTIME_RELEASES=true. Do not set the variable before checking the package contents and approving public disclosure. Never upload live data or secrets. A private artifact store is preferable if server runtime disclosure is unwanted.

VPS operations must continue to honor capacity, backup, finance and migration gates. Do not build on the VPS; use small Git changes and hosted CI. Any removal of development worktrees must follow the shared policy's age, clean-state and verified GitHub-preservation checks. Generated dependencies can be removed after scope and live-reference checks. Do not remove Webuzo entry directories merely because they are empty. Do not remove iRexPro or another app's files.
